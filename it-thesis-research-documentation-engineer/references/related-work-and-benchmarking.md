# Related Work and Benchmarking

## Purpose

Related work should position the project and inform design/evaluation. It is not a catalog of famous tools.

## Build a comparison matrix

For each comparable system/paper/project capture:
- problem and target users;
- scope;
- core workflow;
- architecture/style;
- data/storage model;
- security/roles;
- AI role, if any;
- human oversight;
- evaluation method;
- reproducibility/evidence level;
- strengths;
- limitations;
- relevance to this project.

## Select comparators

Use a portfolio:
1. closest functional comparator;
2. strongest architectural/reference implementation;
3. strongest academic method/paper;
4. security/operations benchmark if material;
5. AI-specific benchmark if material.

## Fair comparison rules

- Compare same scope and population.
- Separate vendor claims from measured evidence.
- Do not rank systems on dimensions not observed.
- Do not call the project superior because it has a feature another report did not mention.
- Explain what is adopted, adapted, or intentionally excluded.

## Gap types

Separate:
- research gap;
- engineering/practice gap;
- local stakeholder gap;
- integration gap;
- documentation/evaluation gap.

A student software project often addresses an engineering or local workflow gap rather than a novel scientific gap. State this accurately.
